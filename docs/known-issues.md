# 已知问题与发布边界

## 审批和 Waiting

- 曾漏报因观察器未信任：用户在 /hooks 审核为 Active 后确认真实 Waiting 可出现。
- 曾无法清理等待：请求带 description、完成不带导致摘要不一致。
  已修复 Bash/apply_patch 匹配，MCP 参数保持完整；旧摘要不能反推输入，
  不随意清空，按正常生命周期清理。同命令并发按次数消费。
- 桌面自动审核曾误报人工 Waiting：已按当前 turn_context reviewer/policy 过滤，
  用户确认本会话不再误报。无日志上下文或其他 Hook 自动放行仍有限制。
- 长命令获批到执行完成之间可能仍显示 Waiting：PostToolUse 是完成回调，不是批准回调。
- 拒绝无完成回调、自动转人工、多问题关联尚未完整验证。
- 用户希望必要的可点击选择卡也触发 Waiting；必要性标记与答复关联尚未实现。
- 不用问号、正文关键词、等待时长或 CPU 占用推测人类是否必须操作。

## 平台

Windows 缺少 Codex writer-lock 发现，最小模式不能完整发现 Codex；
日志模式会回退到近期会话，关闭识别不可靠。真实 Windows/SSH/原生窗口验收未完成。
SSH 远端要求 POSIX shell，Windows PowerShell/CMD 未适配。
Claude Code 依赖提供会话状态 JSON 的版本，不保证所有安装都可识别。

## 服务与资源

独立后台入口减少对终端进程的依赖，但没有自动重启、开机启动或长期稳定性保证。
日志模式初次扫描和远端每次一遍的扫描随日志目录增长；尚无全量性能/内存压力验收。
短时本机测量不能外推 Windows 或 SSH 的性能。频率为每次采集结束后再等待所设间隔。

## 发布

本地测试和 CI 配置不代表真实平台验收。Windows Remark 给出排查入口，不代替适配。
素材授权、代码许可与实际 CI 结果需所有者确认。版本保持 Beta，不宣称成熟稳定版。
