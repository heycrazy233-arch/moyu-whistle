# 奶蛙与悬浮窗搭配建议

用户已确认先按此布局实施，2026-10-21。尚未接入原生窗口，也未修改 floating/ 或 web/assets/whistle.*。

## 位置

推荐一个独立伴随桌宠窗口，默认放在现有悬浮窗右下侧，横向间距 12–16 px。奶蛙显示区约 112×128 px，底部与悬浮窗底部对齐，气泡在奶蛙上方。现有悬浮窗保持收起 420×76、展开 420×590，保留现有标题图标拖拽区及会话列表。

展开/收起时保持桌宠屏幕坐标稳定，详情窗向可用空间展开；不要仅因窗口高度变化把奶蛙上下弹跳。右侧空间不足翻到左侧，再整体约束到屏幕可见范围。允许用户独立拖动奶蛙。位置变化只能由用户拖动或边界修正引起。

不直接放入现有卡片 DOM 外缘：whistle 的 overflow:hidden 和原生窗口边界都会裁掉外部图像。建议复用同一个 PySide6 进程创建第二个轻量窗口，但具体桥接须与前端实现任务对齐。不要增加第二个采集服务或独立通知器。

## 四态映射

读取 ../assets/guada/manifest.json（相对本文件目录）。

| 状态 | 素材 | 展示 |
| --- | --- | --- |
| working | working-cutout.png | 透明角色与小本子，正常静置；不额外添加摇晃 |
| waiting | waiting.gif | 原挥手动画，上方小气泡“有 N 个任务等你” |
| error | error.gif | 用户指定大笑抱头动画，上方明确写“有 N 个任务出错”，用文字弥补表情本身不表达失败的问题 |
| idle | idle.png | 原站立静图，不常驻气泡 |

每次只显示一只；按确认的设计顺序 waiting > error > working > idle 聚合，具体状态供给与前端实现对齐。详情卡片仍分别显示各自状态，不为每条会话复制一只奶蛙。点击奶蛙展开已有悬浮窗；Waiting 可复用 openWaiting，Error 的错误筛选桥接尚待实现。

当前只有 Working 是透明 PNG。其他素材保留原背景，在相同固定包围盒中 contain 显示，外边缘可使用圆角；不能将预览描述为四态都已透明。若要统一裸露桌宠效果，后续另行处理其他三种背景，尤其 GIF 需要逐帧稳定抠图。

## 状态及通知边界

仅可靠的新状态变化触发提醒，沿用现有唯一通知协调器。新增奶蛙气泡后不另弹一次提醒；不要使用模拟 API 事件验收真实通知。暂停、断线和未知状态单独显示连接提示并冻结动画，不转换为 error/idle。无会话可展示休息素材，但不增加 Idle 会话计数。首次连接/重连只建立基线。

交互预览仅使用静帧与明确标注的示例会话，演示位置、状态映射、点击展开及收起，不连接后端。实际动图沿用既有文件。隐藏/减少动态效果时需在真正的渲染器中暂停 GIF，不能只靠 CSS 隐藏。

GIF 支持检查：本机 PySide6 QImageReader 已完整解码 waiting 60 帧、error 239 帧。推荐 QLabel + QMovie 播放；真实窗口播放与暂停恢复仍待实现验收。最新完整交接见根目录 HANDOFF_PET.md。
